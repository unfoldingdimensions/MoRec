**Features in this tier (6):** teleprompter/speaker notes · privacy-mask conveniences · transcript-based word cutting · AI titles/summaries/chapters · BYO S3-compatible upload · multi-clip recording marks.

**Deliverables:** per-feature specs grounded in exact code identifiers, session sequencing, repo conventions, and four copy-paste agent prompts in [2026-09-19-p1-features-prompts.md](2026-09-19-p1-features-prompts.md).

## 0. Scope corrections from codebase verification (read first)

1. **Static privacy blur is already shipped.** `AnnotationType = "text" | "image" | "figure" | "blur"` (types.ts L397) with `blurIntensity`/`blurColor`, rendered in the editor (`AnnotationOverlay.tsx`) **and at export** (`modernFrameRenderer.ts:1496`, `annotationRenderer.ts`). The research's "privacy mask" therefore reduces to conveniences: a **pixelate style** and a one-click quick-mask action (Feature 2, folded into Session A). Scroll-tracking masks stay P2 (AI scope).
2. **No teleprompter exists** — greenfield, HUD-renderer-only work (Session A).
3. **No `safeStorage` usage exists** — the AI-key and upload-secret features introduce it (Sessions B/C). Secrets are encrypted at rest via Electron `safeStorage` in the **main process only**; the renderer never sees plaintext keys.
4. **Multi-source timelines are out of scope.** The editor is single-source (`videoPath`); multi-clip recording is delivered as **mark-and-continue + auto-generated discard trims** (Feature 6, Session D) — the retake UX without touching the capture layer or timeline model. True segment-concat finalize is documented as v2.

## Conventions for every session (identical to the P0 plan)

Branch off latest `main` (`feat/<name>`), one PR per session, conventional commits + `Co-Authored-By: <model (vendor) <noreply@vendor.com>>` trailer. Verify with real output: `npm test`, `npm run lint`, `npm run i18n:check` (strict key parity across 11 locales — every UI string needs all locale files), `npx tsc --noEmit`. CI (`Code Quality`) green before merge. Environment: Mimosa hook blocks raw `git commit`/`git push` in Bash — use the `.tmp/<name>.sh` Write-then-`sh` pattern; do not refactor the advisory-flagged ffmpeg spawn sites in `electron/ipc/export/native-video.ts`; never run `biome format --write` repo-wide (CRLF reformat noise); packaging requires a fresh `npx vite build` before `electron-builder` (stale `dist/` gotcha).

## Feature 1 — Teleprompter / speaker notes (Session A) · Easy

**User story:** "Show my talking points while I record." (FocuSee, Screen Studio, Tella all ship it on paid tiers.)

### Design
- **Notes editor (pre-recording):** a "Notes" popover in the Launch HUD (alongside the mic popover): textarea + font-size control + scroll-speed selector. Persisted via `app-settings` keys `teleprompterNotes`, `teleprompterFontSize`, `teleprompterScrollSpeed` (`loadAppSetting`/`saveAppSetting` in `src/lib/appSettings.ts`; the store is schema-less so no main-process change is required).
- **Prompter (during recording):** the HUD overlay window (see `hudOverlayWindow` in `electron/windows.ts`; HUD renderer lives under `src/components/launch/`) renders a collapsible teleprompter panel: auto-scroll at the configured speed, tap/click to pause, manual drag-to-scroll. Semi-transparent backdrop, theme-aware (the HUD has light/dark state colors). Hidden from capture follows the existing `hideHudFromCapture` behavior — the prompter is HUD chrome, and the existing capture-protection toggle governs it like the rest of the HUD.
- Positioning: fixed right-third panel v1 (no drag-to-reposition; note as v2).

### Tests
- Pure scroll-math util (position = f(elapsed, speed)) colocated test; HUD component test with jsdom docblock + `src/test/electronApiMock.ts`; app-settings round-trip via `register/settings.test.ts` ipcRegistry pattern.

### i18n
`launch.json` keys: `teleprompter`, `notes`, `scrollSpeed`, `prompterPause`, `prompterResume` — ×11 locales.

## Feature 2 — Privacy-mask conveniences (Session A) · Easy

**User story:** "Let me smudge that API key before anyone sees the export." (Blur annotations already ship — this adds the pixelate style and a one-click privacy action.)

### Design
1. **Pixelate style:** extend the blur annotation with a `style` option `blur | pixelate` (new optional field `maskStyle?: "blur" | "pixelate"` on `AnnotationRegion` — optional field = no project-version bump per the lenient `normalizeProjectEditor` pattern; normalize missing → `"blur"`).
   - Editor (`AnnotationOverlay.tsx`): pixelate = draw the region's underlying frame downscaled (factor from `blurIntensity`) and re-upscaled with `imageSmoothingEnabled = false`.
   - Export (`annotationRenderer.ts` / `modernFrameRenderer.ts:1496` area): same downscale/upscale on the export canvas — dependency-free, identical math in both places.
2. **Quick privacy action:** an "Add privacy mask" button in the annotation toolbar that instantly creates a full-frame blur-mask annotation at `endMs = startMs + 5s` (user then drags/resizes — standard annotation gestures) with a suggested high intensity. One click = masked.
3. AnnotationSettingsPanel: style toggle (blur/pixelate) for mask-type annotations.

### Tests
- Pixelate math unit test (downscale factor → block grid); annotationRenderer test: pixelate draws downscaled region (assert canvas calls or output dims); persistence round-trip for `maskStyle`.

### i18n
`addPrivacyMask`, `maskStyleBlur`, `maskStylePixelate` — ×11.

## Feature 3 — Transcript word cutting (Session B) · Medium

**User story:** "Select the words in the transcript where I flubbed, hit Cut, and they're gone from the video." (The Loom/Camtasia/Tella text-editing pattern; v1 of full transcript editing.)

### Design
1. **Word selection in `CaptionListPanel.tsx`:** a "Cut mode" toggle; in cut mode, clicking words toggles their selection (per-word granularity — `CaptionCueWord` carries `startMs`/`endMs` in source time). Selection merges across cues.
2. **Cut operation:** gather selected word spans (source time) → merge adjacent/overlapping (gap ≤ 150 ms) → pad ±40 ms → create `TrimRegion`s via the same conversion pipeline as Feature 2 of P0 (`mapSourceTimeToTimelineTime`, existing trim creation handlers; full undo via `editorHistory`).
3. **Guards (mirror `silenceSuggestions.ts`):** drop cut spans that touch existing zoom/speed regions (reserved-span check with pad); cap total cut at 40% of source (`too-much-selection` status → toast); minimum selected duration 200 ms.
4. **Caption consistency (critical):** cues inside a cut span must be removed, and cues straddling a boundary must be split at it — `captionOps.splitCue` (L129) and `deleteCue` (L213) exist; the cut handler deletes/splits cues so no caption text plays over removed footage. Cue times stay in source time, so no re-timing is needed (the timeline mapping skips trimmed spans).
5. UI feedback: toast `Cut N words (X.Xs)` / `Selection overlaps your zooms — adjust and retry`.

### Tests
- Pure module `transcriptCutting.ts`: span merging/padding, reservation guard, cue split/delete derivation, ratio guard (fast-check invariants: output trims monotonic, non-overlapping, within duration; every remaining cue fully outside cut spans).
- `CaptionListPanel` cut-mode component test (jsdom + electronApiMock).

### i18n
`cutMode`, `cutSelectedWords`, `cutWordsResult`, `selectionOverlapsEdits` — ×11.

## Feature 4 — AI titles, summaries, chapters (Session C) · Medium

**User story:** "Give me a video title, a short summary, and YouTube chapters from my transcript." (Paywalled identically by Loom, Cap, Camtasia.)

### Design
Two engines behind one IPC, chosen automatically:
1. **BYO API engine:** Settings gains an "AI" section: endpoint URL (OpenAI-compatible chat completions, default `https://api.openai.com/v1/chat/completions`), model name, API key. The key is stored **encrypted**: `safeStorage.encryptString` in the main process → base64 into `app-settings.json` under `aiCredentials`; decrypt only in the IPC handler; the renderer receives a boolean `hasKey`, never the key. Requests use `fetch` with a 30 s timeout, one retry on 429, and a strict JSON response contract (`{ title, summary, chapters: [{ startMs, title }] }`) with validation + fallback to heuristics on malformed output.
2. **Heuristic engine (always available, no key):** title = first fluent caption sentence (≤ 80 chars); summary = first two caption sentences; chapters = boundaries at the largest zoom regions (or ≥ 45 s silence boundaries via `analyze-companion-audio-silence` when zooms are absent), minimum chapter length 30 s, max 12 chapters, titled from the caption text in each span.
3. **IPC `summarize-transcript`** (new `electron/ipc/ai/summarize.ts`, registered like `generate-auto-captions`): input `{ videoPath, cues, zoomRegions, durationMs }`; reads the stored credential itself; never logs the key.
4. **UI:** "Generate title & chapters" button in the captions panel → results modal with editable fields → "Save to project" (new optional `ProjectEditorState.metadata = { title?, summary?, chapters? }` — optional field, no version bump) + "Copy YouTube chapters" (renders `m:ss Title` lines from 0:00).

### Tests
- Heuristic engine unit tests (fixture transcripts); response-validation tests (malformed JSON → heuristic fallback); credential encrypt/decrypt round-trip with a mocked `safeStorage`; settings UI test. **Never assert on or log plaintext keys in tests.**

### i18n
`generateTitleChapters`, `aiSection`, `aiEndpoint`, `aiModel`, `aiApiKey`, `apiKeyStored`, `chaptersCopied`, `heuristicModeNote` — ×11.

## Feature 5 — BYO S3-compatible upload (Session C) · Medium-Hard

**User story:** "Upload the finished video to my own S3/R2/Backblaze bucket and hand out the link — no MoRec cloud." (Cap's paid moat; HN users explicitly want sharing without "the cloud part".)

### Design
1. **Settings "Sharing" section:** endpoint (S3-compatible API origin, **https enforced**), region, bucket, access key, secret key (safeStorage-encrypted, same pattern as Feature 4), public base-URL template (`https://cdn.example.com/recordings/`). Optional key-prefix (default `morec/`).
2. **Upload IPC `share-upload-recording`** (new `electron/ipc/share/upload.ts`): single-operation PUT of the file (mp4/gif path from the export result) to `<bucket>/<prefix><fileName>` signed with **AWS SigV4** implemented over `node:crypto` (no SDK dependency — ~80 lines: canonical request, signed headers `host;x-amz-content-sha256;x-amz-date`, payload hash from streamed SHA-256). Body streamed from disk; progress emitted as throttled IPC events (bytes/total every 250 ms) into the same toast/progress UI used by exports. TLS only — reject `http://` endpoints at config time.
3. **Result:** success → copies `<publicBaseURL><fileName>` to the clipboard + toast; failure → typed errors (403 credentials, 404 bucket/endpoint, network) surfaced verbatim minus any credential material.
4. **R2/B2 compatibility:** both accept S3 SigV4 PUT; document endpoint formats in the settings hint text.
5. Launch from: the editor export-complete toast gains a "Share…" action (and the recordings library context menu) — wherever the finished file path is known.

### Tests
- SigV4 signature tests against the official AWS test-vector style (fixed inputs → known signature); credential-redaction test (error paths must not contain the secret); URL-builder unit tests; settings round-trip with mocked safeStorage; upload progress throttle test with a mocked fetch.

### i18n
`sharingSection`, `uploadToBucket`, `uploadProgress`, `uploadComplete`, `linkCopied`, `invalidEndpoint`, `uploadFailed403` — ×11.

**Risks:** SigV4 correctness (mitigated by test vectors); Mimosa may flag the signing/crypto module (expected — document in the PR body; do not weaken the redaction); large-file memory must stay streamed (never `readFile` the whole video).

## Feature 6 — Multi-clip recording: mark & continue (Session D) · Easy-Medium

**User story:** "I flubbed a line 5 minutes in — let me mark it, keep rolling, and cut it in one click afterward." (Vento's founding pain; Tella paywalls multi-clip.)

### Design (v1: marks → auto-discard trims; true concat = documented v2)
1. **During recording:** a "Mark segment" button in the recording HUD (beside stop/pause) appends the current elapsed time to a marks list in the session — persisted via the recording session manifest (`electron/ipc/project/session.ts` `persistRecordingSessionManifest`): add optional `marksMs?: number[]` to `RecordingSessionManifest`, **bump manifest version 3 → 4**, readers accept 1–4 (established pattern; session.ts L80 reader already accepts 1–3). IPC: `mark-recording-segment` registered in `register/recording.ts` alongside `set-recording-state`.
2. **At editor open:** if marks exist, the editor shows a one-time "Multi-clip recording" panel listing the takes: `[start → end]` per mark pair, each with a Keep/Discard toggle (Discard default for the flubbed range **after** each mark — the mark means "everything before this point up to the mark was bad"; copy explains: "marks split the recording; toggle the ranges to discard"). Accepting creates `TrimRegion`s for discarded ranges (identical pipeline to silence removal; undo works).
3. Marks survive crashes: they're persisted per-mark at mark time (atomic manifest write), not only at stop.

### Tests
- Manifest v4 round-trip + v3 payload compatibility (existing session tests pattern); mark IPC test via ipcRegistry; trim-derivation pure-function tests (mark pairs → ranges; edge: mark at 0:00 ignored; overlapping with existing trims preserved).

### i18n
`markSegment`, `multiClipRecording`, `takeRange`, `discardRange`, `keepRange`, `applyMultiClip` — ×11.

**Risks:** elapsed-time clock consistency (marks must use the same pause-aware clock as cursor capture, `getCursorCaptureElapsedMs` — reuse it, do not call Date.now()).
